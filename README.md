# 二南瓜精选 · 鹦鹉饲养套装报价器

一个纯前端 + 零依赖 Python 后端的**可交互报价单系统**。帮朋友配置「两只和尚鹦鹉」完整饲养套装,让他在手机上点选商品、切换套餐、上传图片、生成清单图并一键提交,商家在后台实时查看。

> 一句话定位:把一份「静态报价单」升级成「可交互、可回收、可上线」的小型商业工具。

## ✨ 功能特性

- **可交互选品**:选鹦鹉(多品种、各自数量)、选套餐(学吃/育雏)、选笼子颜色、勾选商品
- **套餐联动**:切换「育雏套餐」自动展开育雏配置(保温箱、奶粉、喂养工具)
- **二选一互斥**:同类商品(如站杆)只能选一个,自动排他
- **推荐高亮**:氛围灯、益生菌等默认勾选 + 「★推荐」标签
- **商品图片**:统一 512×512 正方形裁剪、自动居中、点缩略图看大图
- **示意图高清通道**:配置示意图单独走不裁剪、1600px 高清上传
- **清单导出三件套**:弹窗清单 / 复制纯文本 / Canvas 生成清单图(带日期+提交者)
- **特别需求备注**:末尾自由填写,自动带进清单、清单图、提交数据
- **清单回收**:一键提交到服务器,后台 `/admin` 页面实时查看
- **采购管理**:后台逐项勾选「已采购」、标注**实际采购价**,实时汇总支出与差额;支持把几项**合并成一笔**(实际用同一个东西替代时)、**添加赠送/额外项**;填上**客户实付**后一键生成**给客户的清单**(报价口径,自动抹零凑平到实付金额),另有**自己的成本账单**(跨提交聚合、同名商品自动合并数量);结算过的订单卡片**整卡换配色 + 盖「交易完成」章**,一眼区分
- **订单视图与管理**:顶部「📋 订单 / 🎁 赠品」双视图 + 搜索(客户/备注/商品名) + 筛选(待办/已结算/有赠品,带条数) + 卡片折叠(默认收起,一屏扫完所有单);赠品不再散落在各卡片末尾,而是**集中到赠品视图统一管理**(未指定客户的可直接下拉归属)
- **后台鉴权**:后台查看页、提交数据、采购记录均带 `?key=` 密码保护
- **静态文件白名单**:只放行前端页面与图片资源,`/server.py`、`/submissions.jsonl`、`/data.json` 等后端文件一律 404

## 🛠 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 HTML + CSS + Vanilla JS | 零框架,数据驱动渲染 |
| 后端 | Python 标准库 `http.server` | 零第三方依赖 |
| 存储 | JSON 文件 + JSONL 追加 | `data.json`(商品) / `submissions.jsonl`(提交) / `purchases.json`(采购记录) |
| 图片 | Canvas 前端裁剪 + multipart 上传 | 512 正方形 / 1600 高清双通道 |
| 部署 | Nginx + systemd + Let's Encrypt | Nginx 终结 TLS 并反代到内网 8080;开机自启、崩溃自愈、HTTPS 绿锁 |
| 安全 | 静态文件白名单 + `?key=` 鉴权 | 后端文件与数据文件对公网一律 404 |

**生产架构**:`浏览器 → Nginx(443/80,TLS + 反向代理) → Python(127.0.0.1:8080)`。
早期由 Python 自建 HTTPS,因单线程 accept 循环被恶意握手卡死导致过一次线上故障,后改为 Nginx 接管 TLS。故障复盘见 `TECH_SUMMARY.md`「三·补」。

**核心设计**:所有商品/套餐/选配都是 `data.json` 里的一份数据,前端 `render()` 纯数据驱动渲染。改价格、加商品**不用碰代码**,改 JSON 或直接在页面「编辑模式」点选即可。

## 🚀 快速开始

### 本地运行

```bash
cd app
python3 server.py          # 默认 http://localhost:8000
```

手机同 WiFi 下访问 `http://<电脑IP>:8000` 即可点选。

**手上还没有真实数据,想先看后台长什么样?**

```bash
cd app
DEMO=1 python3 server.py        # 改用 demo/ 里的样例数据启动
```

打开 `http://localhost:8000/admin?key=123456` —— 4 张样例订单,合并项、赠品、
未归属赠品、已结算盖章等场景都覆盖了。数据全是编的,随便点。
详见 [`app/demo/README.md`](./app/demo/README.md)。

### 环境变量

| 变量 | 作用 | 默认 |
|---|---|---|
| `PORT` | 监听端口 | 8000 |
| `SSL` | 设为 `1` 启用 HTTPS | 关 |
| `SSL_CERT` / `SSL_KEY` | 证书路径(启用 SSL 时必填) | 空 |
| `ADMIN_KEY` | 后台查看页密码 | `123456` |
| `DEMO` | 设为 `1` 时改用 `demo/` 下的样例数据 | 关 |

### 后台查看提交 + 采购管理

```
http://localhost:8000/admin?key=<ADMIN_KEY>
```

后台页上半部分是**采购进度条**(已采购数 / 实际支出 / 对应报价 / 差额),下面按提交逐张列出清单。

#### 同一个订单,两份文档

这是整个后台的骨架:**「报价」是给客户看的价,「实花」是你自己的成本,两者绝不混在一张纸上。**

| | 给客户的清单 | 我的账单 |
|---|---|---|
| 单价用 | **报价**(报价单上的价) | **实花**(你的进货成本) |
| 在哪生成 | 每张卡片右边的「📄 客户清单」 | 顶部「📋 我的账单(成本)」 |
| 范围 | 单个客户 | 所有客户汇总 |
| 合计 | 正好等于**客户实际转给你的钱** | 你的总成本 |
| 看的人 | 客户 | 只有你自己 |

#### 账目分成两层,这是整个设计的关键

| | 报价侧(来自朋友提交) | 采购侧(自己操作的) |
|---|---|---|
| 单位 | 报价行,**不可变** | 采购项,可自由组合 |
| 合并 | 粪便清洁纸托 ¥19 + 鸟砂 ¥15 | 一个采购项「无纺布垫纸」——报价记 ¥34、实花 ¥28 |
| 赠品 | 不存在 | 一个采购项——报价记 **0**、实花 ¥38 |

规则只有三条:

1. 每个报价行最多被一个采购项覆盖(不重复记账);
2. 没被任何采购项覆盖 = 还没买;
3. 赠品项报价为 0,只增加实际支出(它照样是你的成本)。

`差额 = 实际支出 − 对应报价`。省钱了显示绿色负数(剩余),超支显示红色正数。赠送项正好用来把剩余预算花掉,差额自然往 ¥0 靠。

#### 给客户的清单怎么"凑"到实付金额

每个客户卡片上有一个 **「💰 客户实付」** 输入框。填上他实际转给你的钱(比如超哥的 800),系统会立刻算出:

```
清单 ¥878  ·  实花 ¥721.7  ·  已付 ¥800  ·  需抹零 ¥78  ·  毛利 ¥78.3
```

打开「📄 客户清单」,输出给客户的那张单子会自动长这样:

```
商品明细合计        ¥878
抹零优惠            −¥78
客户应付合计        ¥800      ← 和客户实际付款分毫不差
```

- 实付 **少于**清单 → 自动生成「抹零优惠」行
- 实付 **多于**清单 → 自动生成「补收」行
- 想加东西而不是抹零?卡片底部「＋ 给这个客户加一项」→ 填**客户报价**,它会按这个价计入清单,差额随之缩小

#### 单子多了怎么找 —— 视图 / 筛选 / 折叠

后台顶部有一条工具条,专治"单子一多就翻不到":

| 工具 | 干什么 |
|---|---|
| **📋 订单 / 🎁 赠品** 切换 | 订单一栏看每张单;赠品那栏把**所有赠品 / 额外项集中到一处**,不管挂在哪个客户下 —— 不用再翻每张卡片的最后一行 |
| **搜索框** | 按客户名 / 留言 / 备注 / **商品名**过滤。搜「鸟砂」能直接列出所有点了鸟砂的单子 |
| **筛选 chips** | 全部 / ⏳ 待办 / ✅ 已结算 / 🎁 有赠品,每个都带条数,不用点进去就知道还剩多少活 |
| **折叠** | 卡片默认收起成两行(客户 + 状态 + 时间 + 金额,以及实付结算条),一屏能扫完所有单子;点「展开」看明细,右上角「全部展开 / 全部收起」一键切换 |

赠品视图里,**未指定客户**的行尾直接挂了「归属客户」下拉 —— 选一下,它就并进那位客户的清单。

订单视图底部如果还有没归属的额外项,会出现一条暖黄提示条,点一下直接跳到赠品视图。

> 折叠只是把明细**藏起来**,DOM 照常渲染 —— 所以勾选、改价、局部刷新那套逻辑一行都不用改。

#### 能做什么

- **勾选「已采购」** —— 自动保存到服务器,绿色高亮,卡片显示「已购 x/y」
- **填实际采购价** —— 留空则按报价计;填了自动变暖黄边框,汇总实时更新
- **🔗 合并成一笔** —— 同一次提交里,实际用同一个东西替代了几项时:点行尾 🔗,勾上被替代的几项,起个新名字(如「无纺布垫纸」)填实际花销。报价仍按原样计入;合并行会标「合」并可展开看覆盖了哪几项,也能一键 ✂️ 拆开
- **🎁 添加赠送项** —— 差额变绿(还剩钱)时,把想多送的东西加上来。**客户报价留空** = 纯赠品(报价计 0、只记你的成本);**填了** = 按这个价计入客户清单。可指定「归属客户」,赠品就会出现在那位客户的清单里(标「赠品」、不收钱——这是最好的口碑)
- **🎁 赠品集中管理** —— 切到「赠品 / 额外」视图,所有赠品不论挂在谁名下都在一处;未指定客户的直接下拉归属
- **📄 客户清单** —— 报价口径,单个客户,合计自动凑平到客户实付,可复制文本 / 打印发客户
- **📋 我的账单(成本)** —— 跨所有提交聚合成本价,同名商品合并数量,算出实际总支出与"比报价省多少",仅自己可见
- **✅ 交易完成** —— 结算过的单子整张卡片换配色(淡青绿底 + 左侧绿条)、头部挂一枚绿色「✅ 交易完成」徽章,并盖上一枚**「交易完成」圆章**;顶部汇总里也会显示「已结算 x / y 单」

#### 交易完成怎么判定

**填了「客户实付」= 这单结算完成**,卡片立刻变绿盖章。不想用自动判定时,结算条右边有「✅ 标记完成 / ↺ 撤销完成」可手动切换。

判定规则(优先级从高到低):

| 状态 | 表现 |
|---|---|
| 手动标记完成 | 始终算完成 |
| 手动撤销 | 始终算未完成,**除非**之后又改了实付 → 回到自动判定 |
| 未手动干预 | **填了客户实付**就算完成 |

> 为什么自动判定不要求"采购项全部勾完"?因为他常会留一两项故意不买(比如客户不要的玩具),那样永远凑不齐"全勾",反而标不了完成。结算的语义本来就是"钱收到了"。
> 但钱收到 ≠ 货买齐,所以印章带上会单独提示 **「还差 N 项没买」**,不让绿色把待办藏起来。

客户清单弹窗底部也会盖同一枚章 —— 给客户的那张单子看着就是"已结清"的样子,复制文本时也会带上 `★ 本单已结清 · 货款已付清 ★`。

采购记录存在服务器 `purchases.json`,刷新、换设备都不丢。早期版本的旧记录会在首次读取时**自动升级**(v1/v2 → v3),老数据不丢(详见 TECH_SUMMARY.md)。
