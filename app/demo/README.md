# demo/ · 演示数据

一份**构造的样例数据**,用来让任何 clone 这个仓库的人,在还没有真实订单的
情况下,直接打开后台看到完整效果。

> **不是真实客户数据。** 姓名、订单、金额全部是编的,只为覆盖各个功能场景。

## 怎么用

在 `app/` 目录下带上演示模式启动:

```bash
DEMO=1 python server.py
```

Windows(PowerShell):

```powershell
$env:DEMO="1"; python server.py
```

然后打开后台(默认密码 `123456`):

```
http://localhost:8000/admin?key=123456
```

## 这份数据覆盖了哪些场景

| 场景 | 在哪看 |
|---|---|
| 普通采购项(勾选 + 填实际采购价) | 「📋 订单」视图 → 张先生 / 陈先生 |
| **合并项** —— 两个报价行合成一笔实花 | 陈先生单 →「无纺布清洁垫纸(合并)」 |
| **赠品** —— 挂名到某位客户 | 张先生单 →「赠 · 藤编鸟窝」 |
| **未归属赠品** —— 还没决定送给谁 | 「🎁 赠品」视图 → 行尾下拉可一步归属 |
| **额外项** —— 手工加的、单独给客户报价 | 李女士单 →「加 · 防溅外出盒」 |
| **已结算** —— 填过客户实付 | 张先生(实付 2200)、陈先生(实付 2180),整卡变绿盖章 |
| **未结算** | 李女士、王女士 |

## 注意

演示模式下在后台点的勾选 / 改价,会直接写进 `demo/purchases.json`。
想恢复成仓库里的原样:

```bash
git checkout app/demo
```

## 两份文件的结构

- `submissions.jsonl` —— 每行一条客户提交,模拟 `/api/submit` 的落盘格式
- `purchases.json` —— 采购记录 v3:`{ver, items, subs}`
  - `items[id]` = 采购项(`source` 声明覆盖了哪些报价行;赠品为 `[]`)
  - `subs[提交id]` = 结算信息(`paid` 客户实付 / `done` 是否完成)

报价行的 key 格式是 `<提交id>|<组序号>|<行序号>`,组序号与 `groups` 数组下标对应。
